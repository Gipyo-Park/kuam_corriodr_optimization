## 1. 현재 시스템 분석

### 1.1 현재 방식 (고정 MSL 기준)
```
altitude_levels = [600.0]  # 고정된 순항 고도 (MSL)
start_vertiport = 150.0 m (MSL)  # 고정 버티포트 고도

회랑 최적화:
  - 순항: 600m MSL (= 450m AGL vs 고정 기준)
  - 리스크 맵 샘플링: 동일 고도 위치에서 모두 동일한 고도에서 샘플
  - RF turn: 고정 고도, 고정 선회 반경
  - 이착륙: 버티포트 고도 150m MSL (고정)
```

### 1.2 한계점
- 지표면 높이 변화 무시 (100m ~ 1000m+ 다양함)
- 산지/도시 구역별로 실제 필요한 안전 고도 무시
- 경제성 미반영 (고도 변화 비용)
- 3D 위험도 그리드 활용 미흡

## 2. 요구사항 (지표면 기준 최적화)

### 2.1 핵심 요구사항
```
사용자 입력:
  - AGL 순항 고도: 450m (지표면으로부터)
  - MOC(Minimum Obstacle Clearance): 예) 100m

회랑 최적화의 변경:
  각 경로 포인트마다:
    altitude_msl[i] = dem_elevation[i] + agl_cruise_height
    
예시:
  위치 A: 지표면 150m → 순항 높이 = 150 + 450 = 600m MSL
  위치 B: 지표면 400m → 순항 높이 = 400 + 450 = 850m MSL  
  위치 C: 지표면 700m → 순항 높이 = 700 + 450 = 1150m MSL
```

### 2.2 물리적 제약
```
1. 클라임/디센트 레이트 (Climb Rate Constraint):
   - 최대 climbrate: ~3-5 m/s (항공기 성능)
   - 세그먼트 거리 d_m에서 고도 변화 ΔH:
       ΔH <= d_m * (climb_rate / ground_speed)
   - 예) 100km 세그먼트, 25 m/s 속도, 3 m/s climb:
       ΔH_max = 100,000 * (3/25) = 12,000m (물리적으로 비현실적)
   - 현실적으로는 수백 m~수천 m 범위

2. 항공기 성능:
   - 어느 고도 이상에서는 climb 불가능
   - 산소 문제, 엔진 성능 저하

3. 에너지 최적화:
   - 높이 올라갈수록 에너지 소비
   - 최적 순항 고도 vs 장애물 회피 트레이드오프
```

### 3.2 아키텍처 재설계

#### 3.2.1 고도 프로파일 생성 (Altitude Profile Generation)
```python
# 의사코드
def generate_altitude_profile(
    path_latlon,              # (N, 2) 경로 위경도
    dem_grid,                 # (Ny, Nx) 지표면 고도
    agl_target_m,             # 450 (지표면으로부터)
    climb_rate_mps,           # 3.0
    ground_speed_mps,         # 25
    lat_lim, lon_lim          # 그리드 범위
):
    """
    각 경로 포인트에서:
    1. DEM에서 지표면 고도 보간 → dem_elev[i]
    2. 순항 고도 계산 → alt_msl[i] = dem_elev[i] + agl_target_m
    3. 클라임 레이트 제약 확인
    4. 필요시 고도 프로파일 평탄화 (smoothing)
    
    반환:
      - altitude_profile_msl: (N,) 각 포인트의 MSL 고도
      - altitude_profile_agl: (N,) 각 포인트의 AGL 고도
      - climb_rate_required: (N-1,) 각 세그먼트의 필요 climbrate
      - feasible: bool 클라임 레이트 제약 만족 여부
    """
```

#### 3.2.2 3D 리스크 평가 수정
```python
# 현재: 고정 고도 (600m MSL)에서만 샘플

def evaluate_path_risks_with_dynamic_altitude(

    altitude_profile,         # (N,) 각 포인트의 실제 순항 고도
    Norm_RT,                  # Ground risk (A, H_time, Ny, Nx)
    AirRisk,                  # (Ny, Nx, Nz*) - 여러 고도
    dem_grid,                 # (Ny, Nx) 지표면
    moc_threshold,            # 100m (최소 안전거리)
    ...
):
    """
    변경점:
    1. 각 점 path[i]에서
    2. altitude_profile[i]을 사용하여 AirRisk 샘플
    3. DEM 기반 MOC 검증: altitude_profile[i] >= dem_grid[i] + moc_threshold
    4. 고도별로 다른 위험도 값 획득 → 목적함수에 반영
    """
```

## 4. 놓치기 쉬운 부분 (Critical Gaps)

### 4.1 이착륙 구간의 고도 전략
```
문제점:
  버티포트 위치별로 다른 지표면 고도
  
시나리오 1: 시작/종료 버티포트 고도가 다른 경우
  Start: 150m MSL (지표 고도)
  End: 250m MSL (지표 고도)
  
  → 이착륙 세그먼트 고도 어떻게 정의?
  
해결 방안:
  1. 각 버티포트별 DEM 고도 확인
  2. 이착륙 타겟 AGL 고도 정의 (예: +450m AGL)
  3. 클라임/디센트 세그먼트에서도 동적 고도 사용
  
코드 영향:
  - build_takeoff_landing() 함수 전체 수정
  - takeoff_complete, landing_entry 고도도 동적으로
  - emergency_points_input도 지표 고도 기반으로 재정의
```

### 4.2 RF Turn 선회 반경 재계산
```
현재: 고정 고도에서 고정 선회 반경 R=(V^2)/(g*tan(φ))

변경 시나리오 1: 고도가 변하면서 선회
  - 고도 변하는 동안 climb/descent 있음
  - 선회 반경이 고도 변화 곡선에 맞춰져야 함
  - 문제: 나선형(helical) 선회 필요
  
변경 시나리오 2: 선회 호 상 점들의 고도
  - 현재: RF arc의 모든 점 = 고정 고도
  - 변경: RF arc 상 각 점마다 다른 고도
  
해결 방안:
  1. 3D 선회 호 생성 (螺旋 모양)
  2. 고도 제약: climbrate 만족
  3. 위험도: 나선형 경로의 연속 샘플링
  
코드 영향:
  - apply_rf_turns() 함수 대재설계
  - 3D 선회 호 생성 (rf_turn.py 전면 수정)
  - 나선형 호의 점 좌표 계산 복잡도 증가
```

### 4.5 리스크 맵 고도 축의 연속성
```
문제: 현재 AirRisk는 12개 고정 슬라이스만
  bird_z_vec = [?, ?, ..., ?]  # 12개 고도
  필요 고도: 1150m MSL (최악의 산지) 가능한가?
  
해결:
  1. 고도 범위 확인: min(bird_z_vec)=?, max(bird_z_vec)=?
  2. 필요한 고도 범위 벗어나면 → 보간
     nearest-neighbor 또는 linear interpolation
  3. 적절한 DEM 해상도로 고도 계산 후
     존재하지 않는 고도에는 가장 가까운 슬라이스 사용
```

### 4.7 경로 거리 및 소요 시간 재산정
```
현재:
  거리 = √((lat차)² + (lon차)²) + (alt차)²  # 3D 유클리드
  시간 = 거리 / speed (근사)
  
변경 시:
  1. 고도 변화로 인한 실제 경로 길이 증가
  2. 클라임/디센트 구간:
     - 고도 변화율 = climbrate
     - 실제 소요 시간 = ΔH / climbrate
     - 수평 진행 속도 감소 (컴포넌트 분해)
  3. 순항 구간에서도 속도가 고도별로 다를 수 있음
  
코드 영향:
  - _path_total_3d_distance_m():
    현재: 단순 고도 차이만 고려
    변경: climbrate 기반 경로 길이/시간 계산
  - 목적함수의 "distance"가 의미하는 바 재정의
    → 실제 Time? 또는 Energy?
```

```
    - 평탄화
    
Step 6: 위험도 재평가 (동적 고도)
  for each point:
    - altitude_profile[i] 기반 샘플
    - 다중 고도에서 보간
    
Step 7: 출력 (고도 프로필 포함)
```

## 10. 결론

**지표면 기준 회랑 최적화로의 전환은 기술적으로 가능하지만, 상당한 규모의 재설계가 필요합니다.**

### 주요 변경 사항
1. **데이터**: DEM 필수 추가
2. **아키텍처**: 고도 프로필 생성 모듈 추가
3. **알고리즘**: 동적 고도 기반 리스크 평가
4. **복잡도**: 특히 3D RF turn 매우 높음
5. **시간**: MVP 기준 ~40-55시간 소요

### 즉시 필요한 것
1. DEM 데이터 확보 (이것이 없으면 진행 불가)
2. Bird map의 정확한 고도 벡터 확인 (보간 범위 결정)
3. 항공기 성능 사양 (climbrate 등)

### 단계별 접근 추천
- **Phase 1**: DEM + 동적 고도 프로필 (비교적 간단)
- **Phase 2**: 제약 추가 (중간 복잡도)
- **Phase 3**: 3D 리스크 (복잡)
- **Phase 4**: RF Turn 3D화 (매우 복잡 - 나중으로 연기 가능)
